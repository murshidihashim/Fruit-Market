## What changed

**Added**
- `docs/workflow/records/`, the single source for every record:
  - `decisions.json`: all decisions, plus a history that can only grow
  - `PLAN-001.json` to `PLAN-003.json`
  - `releases.json`
- `npm run records`: rebuilds `DECISIONS.md`, `CHANGELOG.md`, the pending-approvals block in
  `STATE.md`, and every PDF.
- `npm run records:check` (now the first step of `verify`, so CI runs it). It rejects:
  - broken or duplicate IDs
  - references to things that don't exist
  - an approval without your words and a date
  - an edited history line or a rewritten approval
  - out-of-date views
- `CHANGELOG.md`, in plain player language. It is seeded with version 1.1.0 (what's live now).
- Release step in *Deploy LIVE game*: it refuses to run without release notes for the new version,
  and after a successful deploy it tags the commit (for example `v1.1.1`).

**Changed**
- The PDF export is all-or-nothing. On failure it prints PDF EXPORT BLOCKED and keeps the previous PDFs.
- CI fetches the full history so the records check can compare with the previous commit.

**Removed**
- The hand-edited `DECISIONS.md` (it is now generated).

**Player impact:** none directly. The release process is now traceable: every live build will have a version tag and changelog notes.

## Known issue found (not part of this package)

**The game screen sometimes doesn't appear after rejoining an online room.** The automated tests caught it in 2 of the last 5 CI runs, with no game-code change between them:
- Run 1: after quick match, the second player's game didn't show within 15 s.
- Run 4 (a docs-only commit): after reloading the page mid-match, the game didn't come back within 20 s.

Every other run passed, including locally (more than 8 runs). Real players could hit this when their phone reloads the page or their connection drops.

This is pre-existing and intermittent; the cause isn't known yet. I recommend it as the next package, before Package C: reproduce it by repeating the reconnect test many times, find the cause, fix it, and prove the fix with repeated runs.
