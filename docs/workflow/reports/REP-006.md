## The bug, in plain words

After a player reloaded the page or rejoined an online match, the game sometimes stayed on
**"Connecting to room …"**, even though the match was there and the server had already sent it.

**Why:** the screen started listening for room updates a moment *after* it first appeared. The
connection was already open by then. If the server answered in that gap, the answer was missed, and
the screen waited for a next message that might never come (for example, when everyone was waiting
on that player).

The gap is tiny on a fast computer, so it usually worked. On a slow phone, or when the app is in the
background (browsers pause drawing for hidden tabs), the gap is long and the bug happens often. The
game screen had the same weakness for updates arriving just as it opened.

**Fix:** two small changes in the app (`src/ui/Online.tsx`, `src/ui/game/useGameController.ts`). Right
after starting to listen, each screen checks what has already arrived.
- No server change, no message-format change, no rules or save change.
- Old and new app versions stay compatible.

## Side observations (no action taken)
- **The local test server never finishes closing a socket when the page closes it.** Cloudflare's
  docs say production replies automatically for this project's settings, and the real app never
  waits on a socket it closed itself, so no player impact was found. If it ever matters, the
  documented safe fix is one line in the server's close handler.
- **Playwright's offline mode doesn't break open connections**, so the stress test cuts them with
  a small local relay instead. A "silent" dead connection (no signal at all) isn't simulated yet.
  That would be part of Package C.
