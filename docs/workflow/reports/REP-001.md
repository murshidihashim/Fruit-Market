## 3 · PLAN-001 · Package A: baseline, one verification path, preview and owner brief

**Player problem:** updates reach players without your approval and without one clear pass/fail check, so a bad change could ship silently. You also have no short guide for trying a build yourself.

**Included scope**
1. **One verification command.** `npm run verify` runs lint, typecheck, unit tests and build, and stops at the first failure (about 1 minute). `npm run verify:full` adds the browser suite (about 15 minutes). CI calls `verify:full`. Existing scripts are reused; nothing new is installed.
2. **Preview before publication.**
   - Pushes to `main` run checks only.
   - Production deploys happen only when you trigger *Deploy* (a manual GitHub button), which first runs `verify`.
   - Each change also gets a private Cloudflare **preview URL** that doesn't touch the live game. I'll confirm in Cloudflare's current docs that this is free on your plan; if it isn't, the local preview steps are the fallback.
3. **Branch protection instructions.** A 5-step guide for you to turn it on in GitHub settings (I can't change repository settings). It requires the CI check before merging.
4. **Short records** (reusing the studio docs, not duplicating them):
   - `CLAUDE.md`, about 90 lines: rules, actual commands, preservation constraints, pointers
   - `docs/workflow/STATE.md`, about 500 words
   - `docs/workflow/GAME-BRIEF.md`: audience hypothesis, core loop, session length, exclusions
5. **Owner brief.** `docs/workflow/OWNER-BRIEF.md`: how to open a preview, a 10-minute playtest checklist, and what each check means in plain English.

**Excluded:** any change to rules, balance, art, saves, the server protocol or hosting; paid services; publication; Package B (record automation) and Package C (devices, backups, capacity).

**Roles:** producer (scope), DevOps and release (deploy gate, CI), QA (verify command), technical lead (`CLAUDE.md`). Self-review only; low risk.

**Likely files:** `package.json` (scripts), `.github/workflows/{ci,deploy-web}.yml`, new `CLAUDE.md`, new `docs/workflow/{STATE,GAME-BRIEF,OWNER-BRIEF}.md`, `README.md` (pointer).

**Acceptance (observable)**
- A1. `npm run verify` exits 0 on the current code. A deliberately broken test makes it exit non-zero (shown, then reverted).
- A2. Pushing to `main` does **not** change the live site. Running *Deploy* does, and only after `verify` passes.
- A3. A preview URL (or documented local preview) lets you play the build before you approve publication.
- A4. You can follow `OWNER-BRIEF.md` to open a preview and finish a match, without asking me anything.
- A5. `CLAUDE.md` stays under 120 lines; `STATE.md` stays at or under about 600 words.

**Checks:** `verify` (PASS and FAIL demonstration), one CI run, one manual deploy dry run (after your separate publication approval, or skipped and marked NOT RUN), and the line and word counts.

**Cost and data:** RM0 extra. No player data is touched.

**Risks:** a preview URL feature may need a Cloudflare setting (fallback: local preview). If you forget to press *Deploy*, fixes wait (that's the point).

**Rollback:** revert the package commit; the deploy workflow returns to deploying on every push.
