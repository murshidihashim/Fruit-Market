## 4 · How to publish (after you decide)
1. Make sure CI is green for the candidate. I'll confirm in my reply.
2. GitHub → **Actions** → **Deploy LIVE game** → **Run workflow** → type `PUBLISH` → **Run workflow**.
3. It runs the checks again, confirms the release notes for 1.1.1 exist and that `v1.1.1` isn't
   already used, publishes, smoke-tests the live site, and tags the release.
4. Tell me when it's green. I'll mark 1.1.1 as published (date, commit, tag) and check the live site's version.

If anything else lands on `main` before you press Deploy, ask me to re-check, because the Deploy publishes whatever `main` holds.

## 5 · If something goes wrong after publishing
- **The Deploy run fails:** the old version keeps running. Nothing to undo. Tell me.
- **A problem is found after a successful deploy:**
  - Fastest: Cloudflare dashboard → Workers → `fruit-market` → Deployments → roll back to the
    previous deployment (takes effect in seconds; no data changes in this release, so it's safe).
  - Standard: I prepare 1.1.2 with the change reverted; you press Deploy (about 30 minutes including checks).
