## 1. Where we start

- Online play has two ways in today:
  - **Private rooms**, joined by code or invite link.
  - **Quick match**, which drops you into a stranger's waiting room without showing you who is there.
- Nobody can see which games are open, and players cannot react to each other.
- Each room already runs on its own small server, so a public room costs the same as a private one.
- Free chat is excluded on purpose (GAME-BRIEF: "No chat"; roadmap: moderation burden).

## 2. The proposal (PLAN-112, release 1.26.0)

### A. A public lobby

- **Making a room:** when you create a room you choose **Public** or **Private**. Private stays as today.
- **Finding a room:** a new **Public rooms** list on the online screen shows every public room still waiting for players:
  - the host's name;
  - the seats taken out of 6;
  - the game length;
  - how long it has waited.
- **Joining:** tap Join to take a seat. The list refreshes every few seconds. Rooms that have started or are full drop off.
- **Behind the scenes:** one new small server keeps the list, like the one that already runs quick match. Rooms tell it when they open, fill, start or close.
- **No empty games:** the host can fill empty seats with computer players. After a wait (proposed 60 seconds), the host's Start button offers "Start with computers".
- **Joining mid-game:** joining a game already under way stays impossible. A seat a computer took over can still be taken back by its own player, as today.

### B. Emotes and reactions, with no typing

- **What you can send:** a button by your seat opens 8 reactions:
  - emoji: 😀 👍 👏 😮 😅 😭 🔥 🙏;
  - short preset lines: "Good luck!", "Nice sale!", "Oops!", "Well played".
- **How it shows:** the reaction appears as a bubble over your stall for about 3 seconds, on every phone in the room.
- **No game information:** no fruit pictures, no numbers and no free text. Players cannot signal what is in their crate or set prices together. A test checks that a reaction carries nothing but its id.
- **Limits and muting:**
  - one reaction every 2 seconds per player;
  - tap a player to mute their reactions;
  - a Settings switch hides all reactions.
- **Where it works:** in online rooms only (public, private and quick match). Solo and pass-and-play don't need it.

### C. Not in this plan (it could follow later)

- **Watching a game in progress** (spectating). Every spectator view would need the same secret-price leak checks as a player's, and it would add server load. See question 1.
- **Free chat, friends lists, reporting players.** These stay excluded.

## 3. What changes underneath

- **Protocol:** goes to 5 (new messages for reactions and the public flag).
- **Phones on 1.25.0** are asked to update before going online, as with every protocol change.
- **No game rule changes:** rules version 20 stays.
- **Saved data:** none new. The public list holds only what a waiting room already shows its players: the host's name, the seat count and the settings.
- **Names:** these are already filtered by the name checks (server/names.ts).
- **Privacy page:** will say that a public room shows the host's name to anyone looking for a game.
- **Anonymous counters:** public rooms opened and joined, rooms started with computers, and reactions sent (counts only, never who or what was said).

## 5. Risks and costs

- **Empty lists:** with today's numbers (1 to 11 players a day), the public list will often be empty. Starting with computers (A) means a waiting player still gets a game. Pairing this with quick match keeps the existing way in. Real numbers would grow only with promotion of the game, which is outside this plan.
- **Server cost:** small. The list server answers a request every few seconds per person on that screen, and the reactions are tiny messages. How much the current Cloudflare plan can take is still unmeasured (PLAN-003).
- **Abuse:** limited to preset reactions, so there is nothing to moderate except names, which are already checked.
- **My work:** RM0. No new service and no new dependency.
