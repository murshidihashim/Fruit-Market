## 1. Today

The game keeps anonymous counts only (`docs/ANALYTICS.md`): games started and ended, days reached, final cash to the nearest $25. Daily and Sprint scores keep a name and a score. Online rooms are deleted after 24 hours. Nothing records what a real player bought, stocked or charged, which is why REP-149 to REP-152 rest on computer games.

## 2. What a match record is

The engine is deterministic: the same set-up, seed and moves always give the same game (the Daily market already checks scores this way). So a record does not need to store every sale. It stores:

- the set-up: mode, stalls, days, options, computer levels, perks;
- the seed and the rules, computer-player and app versions;
- every person's moves, in order (buy, crate, prices, bids, favours, upgrades);
- how it ended: finished or left, and on which day.

Replaying a record gives back the whole game: every purchase, crate, price, sale, spoiled piece and the result. A 10-day game is about 3 to 6 KB.

## 3. Privacy

- **Never in a record:** a name, an account ID, a device ID, a room code or an IP address. Names typed for stalls are replaced by seat numbers. Each record has a random number of its own.
- **No link between games.** Two games by the same player cannot be told to be the same player. (Ratings would need that; it is left out here on purpose.)
- **A switch.** "Share anonymous stats" in Settings becomes "Share game data" and covers records. Off: nothing is sent. Online, a match is kept only if every person in it has the switch on.
- **Kept 12 months**, then deleted.
- **The privacy page** says all of this in plain words.
- This changes the project rule "anonymous counters only", so it needs the owner's approval (DEC-140).

## 4. How it works

| Game | Who sends the record | When |
|---|---|---|
| Solo, pass-and-play, League | The app | When the game ends or is left |
| Daily and Sprint | The app, with the score it already sends | At the end |
| Online rooms and quick match | The room server | When the match ends |

- **Where:** a new store on the game server (a SQLite Durable Object, one per month), separate for live and preview. No new service.
- **Abuse:** a size cap, the existing per-IP limit, shape checks, unknown versions refused.
- **Reading it:** a key-protected download and `npm run matches`, which replays records and prints tables: orders with two sellers, prices against the customer's top price, fruit spoiled, win share by perk and buying order, where games are left.

## 5. Steps

4. Release, on the owner's word. A first findings report after two weeks of real games.

## 6. Risks and costs

- **Cost:** RM0 expected. The Cloudflare plan's storage limit is not known (STATE lists the plan tier as unknown); step 2 starts by reading it. If it is too small the work stops and asks.
- **No backup** of records in this plan. Losing the store loses history, not the game.
- **Older app versions** send nothing; records start with the release.
- **Computer-player changes:** a record replays only with the versions it was made with, so the reader keeps old versions' results as they were stored at the end of the game (final cash and sales are saved beside the moves as a check).
- **Children:** the audience is 12 and up. Records hold no personal data, and the switch is in Settings.
